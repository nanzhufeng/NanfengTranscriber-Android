# 中英混合转写准确率策略

## 结论

不把“换成完整 Whisper large-v3”当成唯一方案。当前更合理的产品方向是先利用媒体已有的可靠文字，再让三档语音识别负责没有字幕的内容；底层允许使用不同引擎，并通过短语音切分、上下文、术语词表和低置信片段二次识别提高准确率。

版本 15 已完整打通零成本的“内嵌字幕优先”：即使语音模型未下载，UI 也允许先启动预检；在加载 Whisper 前检查 MP4 等容器中的文字字幕轨，可信字幕直接解封装为带时间轴转写结果；找不到时才进入模型检查并回退语音识别。它能解决软字幕/内封字幕，不能读取已经烧录进画面像素的硬字幕；硬字幕后续需要抽帧、字幕区域检测和 OCR，并仍应与音频转写交叉核对。

“最佳”不是只有一个模型：长音视频、句内中英切换、专业名词、时间戳和手机资源之间存在不同取舍。正式 UI 仍保持三档，底层候选池则至少比较以下四条路线，进入正式档位前必须用同一批真实中英混合素材完成 Find N5 门禁：

- Whisper Large V3 Turbo：当前兼容基线，时间戳链路成熟；Turbo 是完整 large-v3 的裁剪加速版，不能代表最高精度上限。
- SenseVoice Small INT8：约 228 MB，适合作为低资源、快速中英混合候选，但不预设它一定是最高精度。
- Paraformer / FunASR：把中文、英文、时间戳和热词定制作为重点对照，尤其适合人名、软件名、品牌名等固定词汇。
- Qwen3-ASR：0.6B 作为可上手机的高精度候选，1.7B 只作实验室准确率上限对照；0.6B 也不能只凭榜单直接判定优于 Whisper。

建议候选档位：

1. 极速：Whisper Base，保留现有兼容与速度基线。
2. 均衡：SenseVoice Small INT8，约 228 MB，官方提供 Android / ONNX 路径，原生覆盖普通话、英语、粤语、日语和韩语。
3. 高精度：Qwen3-ASR 0.6B INT8 或现有 Whisper Large V3 Turbo 二者实测择优。Qwen3-ASR 0.6B 的 sherpa-onnx 导出约 937 MB，已有 Kotlin / Android 支持；不能只凭模型宣传替换现有高质量档。

完整 Whisper large-v3、Qwen3-ASR 1.7B 和较大的 Paraformer 变体只做实验室对照，不直接进入手机普通选项。最终很可能不是“一个模型包打天下”，而是均衡档单次识别、高精度档对少量困难片段选择性复核。

## 不依赖更大模型的补强

- 优先提取视频内嵌文字字幕轨，保留原时间轴；没有可读轨道再启动 ASR，避免把已有准确文本重新听写一遍。
- 用 VAD 按真实语音停顿切成约 15–30 秒片段，不再把 5 分钟硬块直接交给单次语言判断。
- 在识别前做轻量音频前端：双声道择优/混合、响度归一化、削峰和可控降噪；原始音轨保留，避免强降噪把辅音或英文词尾一起抹掉。
- 相邻片段保留少量重叠，并把上一段末尾文字作为下一段上下文；断点仍按稳定媒体时间保存。
- 增加任务级术语词表，适合人名、软件名、品牌名和中英文专业词；任务开始后冻结，确保后台恢复结果一致。
- 记录片段级语言和置信证据；只把低置信或语言突变片段交给高精度档二次识别，避免整段两小时素材重复推理。
- 把“识别后纠错”与“翻译润色”拆开：优先使用本地术语映射、数字/标点规则和邻段一致性校正，不需要 API Key，也不会产生服务费用；原始结果始终保留，可随时对照。可选云端润色仍维持默认关闭。

## 实施顺序

1. 先建立可替换识别引擎接口和同素材基准工具，不改用户看到的三档数量。
2. 第一轮在 Find N5 对比现有 Whisper、SenseVoice INT8、Qwen3-ASR 0.6B INT8；Paraformer 作为热词能力对照。
3. 同时落地 VAD、片段重叠、术语词表、可见分段进度和低置信片段标记；这些收益不依赖持续付费。
4. 只有通过准确率、速度、峰值内存、温度、断点恢复和两小时稳定性门禁的组合，才替换正式三档映射。模型仍一次下载长期缓存，更新 App 不重复下载。

## 验收口径

同一批真实素材至少包含普通话、英语、中英句内切换、专业名词、多人声、背景音乐和较差录音。分别记录：中文 CER、英文 WER、中英术语保留率、时间戳偏差、实时系数、峰值 PSS、温度、模型大小、断点恢复和两小时稳定性。

正式档位只能由同一素材的实测结果决定；模型参数量、官方综合榜单或单条演示不能替代 Find N5 真实链路。
