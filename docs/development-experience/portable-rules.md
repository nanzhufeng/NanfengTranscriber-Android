# 可迁移规则与增量验收模板

这些是此前 checkpoint 增量的可携带摘要；共享产品/工作流标准仍为唯一全局入口，不另建重复全球 Skill。本轮完整复盘按用户明确要求新增五类项目专属 Skills，入口见根 AGENTS；整合后的分类正文见 [可迁移开发经验](../可迁移开发经验.md)。具体包名、像素、模型和哈希留在项目合同，不复制为所有 App 的固定值。

## 触发 → 执行 → 验证 → 禁止

1. 通知、历史和浮层消费同一长任务：先确定持久状态和唯一进度所有者，阶段与进度分离；用完成/失败/取消路径及 late callback 验证；禁止另算比例或仅用文案代替完成提交。
2. Android 后台服务持有资源：以受测 finally seam 统一释放，锁使用有界租约；验证取消、执行异常和查询异常的清理；禁止以一次短样本通过承诺无限后台稳定。
3. Android 跨进程绑定影响重要性：判断界面可见必须区分 Activity 和 FGS/绑定提升；用真实退到桌面路径与重要性回归验证；禁止把进程重要性阈值当作 Activity 可见的充分条件。
4. Android 背景切换改变轮廓：背景设置可能重置 padding，几何和文字安全区必须在其后恢复；同数据检查简洁/详细及标题边缘；禁止只改最小宽度而忽略实际内边距和触控范围。
5. 一个辅助提示有两种密度：默认必要信息，用户操作才展开，任务切换恢复约定默认；测试更新不会擅自展开；禁止把所有诊断/说明长期塞入紧凑提示。
6. 模型缓存与远端任务同时存在：分别归属本地资产和远端任务 checkpoint；验证匹配恢复与提交状态不明时防重复提交；禁止把 Mock 成功当作真实服务/计费验收。
7. 用户要 checkpoint 而非重发：冻结现有源码与产物，补真正缺失的合同/证据后本地提交；检查 Git 核心跟踪与包哈希；禁止重复打包改变已经安装或发布的字节。
8. 上传迟迟不完成：先测发送量和服务端资产状态，只调整本轮传输并回读服务端 digest；禁止无证据归因、全局改代理或在附件不完整时宣布发布完成。

## 可复制的增量验收模板

每次增量填写以下记录，不复制历史统计冒充新结果：

- 输入与第一用户任务：用户要改变什么，明确不改变什么。
- 唯一所有者：持久状态、任务进度、结果、外部动作分别由谁负责。
- 对照基线：源码提交、产物身份、已通过证据的版本和时间。
- 缺失增量：哪些真正新变化尚未纳入代码、合同或验证；已完成部分只做引用。
- 红灯与回归：原失败信号、最小命令、修复/合同更新后相同信号的结果。
- 证据分层：自动检查、构建、模拟器、真机、真实服务分别写 PASS / 未运行 / 尚缺证据。
- 数据与授权：用户文件、设备、权限、计费、签名和远端写入的许可边界。
- checkpoint：仅显式纳入本轮文件；记录未动 WIP、回滚点与是否推送。
